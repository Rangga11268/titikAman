Pemerintah / Kelurahan

Aktor & Tanggung Jawab

Warga Terdampak

Warga Umum

  • Mengirim laporan koordinat SOS saat terjebak banjir.
  • Melakukan input estimasi tinggi air di jalanannya (crowdsourcing).
  • Mengakses info status TMA & Peta sebaran banjir.
  • Menyalurkan donasi barang darurat ke posko.
Relawan Lapangan

Relawan Kebencanaan

  • Memantau sinyal SOS prioritas (korban rentan).
  • Menerima tugas penyelamatan korban.
  • Melaporkan status misi jika korban telah tiba di posko dengan aman.
Pengelola Posko

Petugas Pengungsian

  • Mengubah data kapasitas pengungsi aktif di lapangan.
  • Menginput barang kebutuhan darurat (selimut, makanan bayi).
  • Konfirmasi fisik donasi yang datang di posko.
Admin BPBD

Aparatur / BPBD

  • Memperbarui TMA secara periodik pada pintu air utama.
  • Validasi (Terima/Tolak) laporan kiriman genangan air dari warga.
  • Memantau rekap keseluruhan mitigasi bencana di dashboard.

Kamus Data & Relasi Relasional

Penjelasan rinci mengenai relasi kunci (foreign key) dan integritas database untuk 8 tabel yang digunakan oleh sistem.

Penjelasan Relasi Antar Tabel

Relasi / Foreign Key Tabel Asal (Parent) Tabel Tujuan (Child) Jenis Relasi Aturan Aksi Hapus (On Delete)
reporter_id `users` `flood_reports` One-to-Many (1 Warga -> N Laporan) Cascade
gate_id `water_gates` `flood_reports` One-to-Many (1 Pintu Air -> N Laporan) Set Null (Laporan tetap ada jika data Pintu Air dihapus)
shelter_id `shelters` `shelter_needs` One-to-Many (1 Posko -> N Kebutuhan Barang) Cascade
donor_id `users` `donations` One-to-Many (1 User -> N Donasi) Cascade
need_id `shelter_needs` `donations` One-to-Many (1 Kebutuhan -> N Log Kirim) Cascade
sender_id `users` `sos_requests` One-to-Many (1 Warga -> N SOS Request) Cascade
sos_id `sos_requests` `rescue_missions` One-to-Many (1 SOS -> N Tugas Penyelamatan) Cascade
volunteer_id `users` `rescue_missions` One-to-Many (1 Relawan -> N Misi Evakuasi) Cascade

Catatan Desain & Optimasi

1. **Integrasi Geospasial**: Kolom `latitude` dan `longitude` disimpan dalam format `decimal(10,8)` dan `decimal(11,8)` di tabel `shelters`, `flood_reports`, dan `sos_requests`. Ini memberikan presisi hingga rentang ~1 milimeter di atas tanah, yang sangat cukup untuk penemuan korban terjebak banjir.

2. **Pola Evakuasi Kedaruratan**: Kolom `people_trapped`, `elderly_count`, `infant_count`, dan `pregnant_count` di tabel `sos_requests` memungkinkan relawan lapangan memfilter misi evakuasi berdasarkan tingkat kerentanan korban. SOS yang mengandung balita, lansia, atau ibu hamil akan ditandai dengan label prioritas utama.

3. **Sistem Peran (Role-based Access)**: Peran user (`role`) menggunakan enum bawaan database MySQL/SQLite untuk mencegah dependensi library luar yang berat di backend. Pengaturan role ini mengikat hak akses warga (`warga`), relawan (`relawan`), pengelola (`pengelola`), dan BPBD (`admin`) secara aman.
